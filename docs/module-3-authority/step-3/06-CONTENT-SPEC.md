# Content Specification Document

## Module 3 – Authority System

### Step 3 – Profile & Portfolio Strategy

**Version:** 1.0
**Status:** Content & AI Ready

---

# 1. Purpose

This document defines all user-facing content displayed within Step 3.

It specifies:
* Page copy
* Headings
* Educational explanations
* AI-generated recommendations
* Tone of voice
* Personalization rules
* Tooltips
* Placeholders
* Validation messages
* Empty state copy
* Error copy
* Success copy
* Microcopy
* Content length standards

The goal is to ensure every word has a purpose.

---

# 2. Content Philosophy

Every piece of content should achieve one of these goals:
* Educate
* Build confidence
* Reduce uncertainty
* Explain recommendations
* Encourage action

Content should never exist purely to fill space.

---

# 3. Tone of Voice

The product should sound like:
* An experienced mentor
* A trusted consultant
* A supportive strategist

Not:
* A marketing website
* A textbook
* A robotic AI
* A motivational speaker

Writing characteristics:
* Clear
* Concise
* Friendly
* Professional
* Educational
* Action-oriented
* Evidence-based

Avoid:
* Buzzwords
* Corporate jargon
* Filler sentences
* Overpromising
* Fear-based language

---

# 4. Reading Level

Target:
* Easy to scan
* Plain language
* Short paragraphs
* One primary idea per paragraph

Assume users are beginners unless prior data indicates advanced expertise.

---

# 5. Content Hierarchy

Every section should follow this order:
1. Section Title
2. Purpose Statement
3. Personalized AI Summary
4. Recommendations
5. Why This Matters
6. Examples (if useful)
7. Actions
8. Advanced Tips (optional)

Users should understand the recommendation before seeing implementation details.

---

# 6. Heading Guidelines

Headings should:
* Describe outcomes rather than features.
* Be concise.
* Clearly indicate the user's next area of focus.

Examples:
"Choose Your Best Platforms"
instead of
"Platform Configuration"

---

# 7. Body Copy Guidelines

Body text should:
* Explain before instructing.
* Use active voice.
* Focus on user benefit.
* Remain concise.

Recommended maximum:
2–4 sentences per content block before introducing visual separation.

---

# 8. AI Recommendation Format

Every AI recommendation should include:
1. Recommendation
2. Confidence / Priority (optional)
3. Why It Matters
4. Expected Benefit
5. Suggested Next Action

Template:
Recommendation
↓
Reason
↓
Impact
↓
Action

Never present recommendations without context.

---

# 9. Personalization Rules

Every recommendation must adapt based on:
* Authority Position
* Career Path
* Experience Level
* Target Client
* Offer Blueprint
* Proof Strategy
* Existing Platforms
* Existing Portfolio
* Missing Assets
* Industry Requirements

The AI should reference user-specific context naturally rather than repeating raw data.

---

# 10. Dynamic Content Rules

The system should dynamically adjust:
* Examples
* Platform suggestions
* Portfolio sections
* Trust indicators
* Content ideas
* Implementation priorities
* Roadmap sequencing

Avoid generic advice that ignores user inputs.

---

# 11. Placeholder Guidelines

Placeholders should guide input, not replace labels.
Examples should demonstrate expected content rather than generic text.

Good:
"Describe the transformation your project delivered."

Poor:
"Enter text..."

---

# 12. Tooltip Guidelines

Tooltips should:
* Explain unfamiliar concepts.
* Clarify recommendations.
* Provide concise educational context.
* Stay under approximately two short sentences.

Tooltips should not repeat visible content.

---

# 13. Validation Messages

Validation messages should:
* Explain what is wrong.
* Explain how to fix it.
* Avoid blaming the user.

Good:
"Please provide a portfolio title before continuing."

Poor:
"Invalid input."

---

# 14. Empty State Content

Every empty state should include:
* Friendly explanation
* Why the section is empty
* What the user should do next
* Primary recovery action

Users should always know how to proceed.

---

# 15. Loading Messages

Loading messages should communicate progress.

Examples:
* Reviewing your authority strategy...
* Designing your profile recommendations...
* Organizing your portfolio structure...
* Prioritizing your trust signals...

Rotate messages for long-running AI operations to reassure users that work is progressing.

---

# 16. Error Messages

Error messages should:
* Explain the issue in plain language.
* Avoid technical terminology.
* Offer a recovery action.
* Preserve user confidence.

Every error should answer:
* What happened?
* What can I do now?

---

# 17. Success Messages

Success messages should:
* Confirm completion.
* Reinforce progress.
* Suggest the next logical action.

Keep success messages brief and actionable.

---

# 18. Educational Content

Educational content should appear only when it increases understanding.

Every educational block should answer:
* Why this recommendation exists.
* Why it matters.
* How it affects the user's authority.

Avoid lengthy tutorials inside the page. Provide just enough context to support informed decisions.

---

# 19. AI Explanation Rules

Every AI-generated recommendation should answer:
* Why was this recommended?
* Which user information influenced it?
* What problem does it solve?
* What outcome should the user expect?

Recommendations should feel transparent rather than mysterious.

---

# 20. Recommendation Prioritization

Recommendations should be grouped by:
Critical
↓
High Value
↓
Recommended
↓
Optional

This helps users make informed decisions without feeling overwhelmed.

---

# 21. Microcopy Standards

Buttons:
Use action-oriented labels.

Examples:
* Save Strategy
* Edit Recommendation
* Continue
* Review
* Regenerate

Avoid vague labels such as:
* Submit
* OK
* Next

---

# 22. Character Limits

Recommended limits:
* Page Title: ≤ 60 characters
* Section Heading: ≤ 50 characters
* Recommendation Title: ≤ 70 characters
* Tooltip: ≤ 150 characters
* Button Label: ≤ 24 characters
* Validation Message: ≤ 120 characters
* Success Message: ≤ 100 characters
* Empty State Title: ≤ 60 characters
* Empty State Description: ≤ 220 characters

Keep content concise to improve scanability.

---

# 23. Content Consistency Rules

Use consistent terminology throughout the product.

For example, avoid switching between:
* Portfolio / Website
* Authority / Reputation
* Recommendation / Suggestion
* Client / Customer

Choose one preferred term for each concept and use it consistently.

---

# 24. Localization Readiness

All content should be:
* Free of culture-specific idioms.
* Easy to translate.
* Avoid hardcoded dates, numbers, or examples.
* Separate dynamic variables from static copy.

This prepares the product for future multilingual support.

---

# 25. AI Safety & Content Guardrails

The AI should:
* Avoid inventing user achievements.
* Clearly distinguish recommendations from facts.
* Avoid exaggerated claims or guarantees.
* Never imply outcomes that cannot be supported.
* Explain uncertainty when recommendations are based on incomplete information.

---

# 26. Definition of Done

The Content Specification is complete when:
* Every user-facing text element has a defined purpose.
* Tone and terminology are consistent.
* AI recommendations follow a standardized structure.
* Personalization rules are documented.
* Placeholders, tooltips, validation messages, and microcopy are specified.
* Content remains educational, concise, and actionable across all user states.

This document becomes the single source of truth for writers, designers, developers, and AI systems, ensuring that every word in the interface contributes to clarity, trust, and user success rather than simply filling space.
